# React/Shiny Parity Audit

This file documents the parity contract for the React/FastAPI rebuild. The
machine-readable source of truth is generated by:

```bash
mlb-show-terminal audit-parity --repo . --output-json artifacts/audit/parity_matrix.json --output-md artifacts/audit/parity_matrix.md
```

Runtime hosts must not write these artifacts. Generate them locally or in CI and
commit the reviewed output when the parity surface changes.

## Market Scan

- Partitions must remain explicit: Flip Buys, Upgrade Buys, Holds, Sells, and
  Dropped / Invalid.
- Flip tables render executable microstructure math only: raw bid, raw ask,
  after-tax sale, profit, ROI, spread, liquidity, and flip reason codes.
- Upgrade tables render threshold probabilities: next threshold, distance to
  threshold, distance to 85/90, P(Cross), P(Up), P(Down), confidence, score,
  action, and upgrade reason codes.
- Forecast gates are diagnostics and must never block flip BUY/SELL or roster
  upgrade speculation.
- UUID parsing extracts every 32-hex token, lowercases it, preserves first-seen
  order, reports duplicates and invalid tokens, and never rewrites valid UUIDs.
- Scan progress is transient in memory and reports total, completed, current
  UUID/card, dropped count, invalid count, status, and timestamps.

## Card Analysis

- Forecasts are diagnostic-only and include forecast cone, multi-horizon EV,
  price-history summary, quant diagnostics, walk-forward CV, calibration bins,
  gates, tier, and verdict state.
- The target panel must show the card identity, flip signal, upgrade signal,
  liquidity, freshness/source metadata, and reason-code pills.

## Validate And Overall

- Validate includes manual flip formula validation plus upgrade backtesting.
- Overall includes app health, runtime constraints, last scan summary, tier
  distribution, and market health medians from the last scan.
