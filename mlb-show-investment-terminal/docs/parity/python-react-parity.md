# Python/React Parity Audit

This file documents the current parity contract for the React/FastAPI terminal.
The machine-readable parity audit can still be generated by:

```bash
mlb-show-terminal audit-parity --repo . --output-json artifacts/audit/parity_matrix.json --output-md artifacts/audit/parity_matrix.md
```

Generate audit artifacts locally or in CI and commit reviewed output when the
parity surface changes.

## Source Of Truth

- Python owns market math, forecast diagnostics, inventory scoring, backtests,
  persistence, provenance, and final strategy semantics.
- React renders Python output and may not invent trade labels.
- `strategy.*` is the preferred API contract. Legacy flat fields remain only for
  compatibility while the UI migration continues.

## Market Scan

- Scanner rows must expose raw ask, raw bid, after-tax resale value, net spread,
  flip ROI, directional EV, `P(profit)`, liquidity, inventory risk, source
  timestamp, coverage tier, performance tier, and final action.
- Final actions must come from the composite strategy matrix:
  `INSTANT FLIP ONLY`, `SPREAD CAPTURE ONLY`, `FLIP OR SHORT HOLD`,
  `SPECULATIVE HOLD`, `WATCHLIST / NO MODEL TRADE`, `AVOID`, or
  `AVOID / MANUAL REVIEW`.
- A bearish or negative-EV directional forecast must never produce final
  `INVESTABLE`.
- UUID parsing extracts every 32-hex token, lowercases it, preserves first-seen
  order, reports duplicates and invalid tokens, and never rewrites valid UUIDs.
- Scan progress is transient in memory and reports total, completed, current
  UUID/card, dropped count, invalid count, status, and timestamps.

## Card Analysis

- Target / Trade Ticket must show card identity, source link, freshness,
  listing timestamp, ask, bid, after-tax value, flip verdict, directional
  verdict, inventory verdict, final action, and plain-English explanation.
- Directional `INVESTABLE` is a nested directional label only. It must include
  a recommended hold horizon when positive.
- Matt Olson regression shape:
  positive spread plus bearish EV and `P(profit)=0` maps to
  `INSTANT FLIP ONLY` when liquidity/freshness pass, never final
  `INVESTABLE`.

## Validation And Backtesting

- Responses must separate `data_coverage_tier` from
  `performance_validation_tier`.
- The legacy `validation_tier` field mirrors `performance_validation_tier`.
- Coverage tiers describe retained real-history depth only.
- Performance tiers require after-tax baseline comparison and calibration
  evidence; losing strategies can have nontrivial coverage but low performance.
- Historical labels must come from real pre/post roster artifacts, retained The
  Show `price_history`, retained The Show `completed_orders`, Supabase
  snapshots, or user-authored ledger rows.
- No synthetic production data or fake backfill is allowed.

## Historical Backfill

- `snapshot-live-cards` captures live listing state; `--enrich-mlb-stats` adds
  flat `recent_` / `season_` columns so CSV snapshots can be scored later.
- `score-snapshot` writes prediction rows with prefixed probability columns such
  as `upgrade_p_cross_next_threshold`.
- `build-upgrade-labels` compares pre/post OVR and emits
  `crossed_next_threshold` labels.
- `backtest-upgrades` and `backfill-upgrades` require enough matched labels
  before `status: available` is returned.
- `backtest-historical-snapshots` uses retained The Show bid/ask price-history
  rows. It validates price paths, not full queue/depth execution.
- `backtest-completed-orders` uses retained completed-sale prints. It validates
  directional sale-price outcomes only.

## Persistence Parity

- Browser code must never receive service credentials.
- Public scan/analyze requests skip persistence collection unless the trusted
  write token is supplied.
- Execution ledger writes require `X-Terminal-Write-Token` when persistence is
  configured.
- Read-only degraded mode is valid and must be visible in the UI and health
  payload.
